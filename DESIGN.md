# Enterprise Design System Rules & Durable Truth (DESIGN.md)

This document establishes the binding design constraints, token usage policies, and layout guidelines for all code generated by AI coding agents within this workspace.

---

## 1. Core Principles (Anti-Slop Directives)

1. **Token Strictness**: Never use arbitrary hex colors (e.g. `#1e293b`), random margins (e.g. `mt-[23px]`), or custom inline font sizes. All styling must derive from approved design tokens or standard design system component props.
2. **Predictable Information Density**: Enterprise B2B software demands clarity and efficient scanning. Avoid excessive whitespace, oversized hero banners on data views, and multi-layered nested cards ("cards inside cards").
3. **No Unnecessary Status Chips**: Do not wrap every table cell or text label in a colored badge ("status-chip soup"). Use colored badges exclusively for actionable or critical lifecycle states.
4. **Resilient States by Default**: Every view, dashboard, and form generated MUST explicitly handle:
   - **Loading State**: Cohesive skeleton layouts matching the expected content geometry.
   - **Empty State**: Clear illustrated empty state with a primary call to action when zero records exist.
   - **Error State**: Inline alert with error boundary diagnostics and recovery action.

---

## 2. Component Taxonomy & Conventions

### Primitives & Complex Controls
* **Buttons**: Use explicit variant attributes (`primary`, `secondary`, `tertiary`, `danger`). Do not construct buttons using raw `<button>` HTML or `<div>` with click handlers.
* **Data Grids**: Use the design system `DataTable` component. Provide `columns`, `rows`, sorting, pagination, and empty state props.
* **Forms**: Group related controls inside `FormGroup`. Always pair inputs with visible, accessible `<Label>` and inline helper/validation text.
* **Modals & Drawers**: Modals for destructive or focused quick decisions; Drawers for detail viewing and multi-field editing.

---

## 3. Theming & Token Usage

* **Corporate B2B Theme (`enterprise-dark` / `enterprise-light`)**:
  - Primary Action: Deep Indigo / Corporate Blue (`--color-primary`)
  - Background Neutral: Subtle layered slates (`--color-surface-base`, `--color-surface-raised`)
  - Text Hierarchy: Primary high-contrast (`--color-text-primary`), Secondary muted (`--color-text-secondary`)
* **Client Service Theme (e.g. `client-warm-sage`)**:
  - Accents: Sage green / Warm stone
  - Typography: Editorial serif headings with clean sans details

---

## 4. Impeccable Refinement Protocol

Before finalizing any generated frontend page, run the Impeccable critique pass:
* `/distill`: Remove redundant grouping wrappers, clarify the primary visual metric, and balance typographic weight.
* `/polish`: Eliminate AI styling tells (random italicized words, AI beige backgrounds, inconsistent border radii).
* `/clarify`: Replace vague CTA labels ("Submit", "Click here") with action-oriented verbs ("Generate Invoice", "Confirm Appointment").
* `/harden`: Verify WCAG AA contrast (minimum 4.5:1), keyboard focus indicators, and error boundaries.
