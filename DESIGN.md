# Enterprise Design System Rules & Durable Truth (DESIGN.md)

This document establishes the binding design constraints, token usage policies, architectural governance, and layout rules for all code generated by AI coding agents within this workspace.

---

## 1. Core Principles (Anti-Slop & Anti-Force-Fit Directives)

1. **Anti-Force-Fit Rule (MANDATORY)**: Never force an arbitrary PRD or Visual Mockup into a rigid pre-packaged recipe stamp.
   - If the user's intent or visual mockup aligns with a canonical pattern, use the corresponding recipe.
   - If the intent requires an open layout (e.g. split-screen telemetry, timeline, interactive canvas, bespoke workflow, or visual mockup layout), set `recipe: null`, declare `layout_type: "open_composition"`, and build using atomic components and design tokens.
2. **Token Strictness**: Never use arbitrary hex colors (e.g. `#1e293b`), random margins (e.g. `mt-[23px]`), or custom inline font sizes. All styling must derive from approved design tokens or standard design system component props.
3. **Predictable Information Density**: Enterprise B2B software demands clarity and efficient scanning. Avoid excessive whitespace, oversized hero banners on data views, and multi-layered nested cards ("cards inside cards").
4. **No Unnecessary Status Chips**: Do not wrap every table cell or text label in a colored badge ("status-chip soup"). Use colored badges exclusively for actionable or critical lifecycle states.
5. **Resilient States by Default**: Every view, dashboard, and form generated MUST explicitly handle:
   - **Loading State**: Cohesive skeleton layouts matching the expected content geometry.
   - **Empty State**: Clear illustrated empty state with a primary call to action when zero records exist.
   - **Error State**: Inline alert with error boundary diagnostics and recovery action.

## 2. Multi-Environment Architecture & Auto-Detection

The system supports 3 operational environments with zero-config auto-detection:

| Mode | Environment | Component Package | Dependency Target | Detection Mechanism |
| :--- | :--- | :--- | :--- | :--- |
| **`carbon`** | Local Personal / Non-Enterprise | `@carbon/react` | Public npm (npmjs.com) | Default fallback; zero VPN or Artifactory credentials needed |
| **`wbg`** | Local Enterprise Workstation | `@wbg/design-system` | Private WBG Artifactory | Active Azure DevOps PAT or reachable internal Artifactory |
| **`cloud`** | Azure App Service Container | Dynamic (`@carbon/react` / `@wbg`) | Linux Python 3.11 / Oryx | `WEBSITE_SITE_NAME` or `MCP_MODE=uvicorn` |

*Override*: Developers can explicitly enforce mode via `DESIGN_SYSTEM_MODE=carbon|wbg|cloud`.

## 3. Candidate Dev Ports & Universal Probing

Frontend applications may run across diverse dev servers and ports:
* **Port 3000**: Next.js / Create-React-App default
* **Port 3001**: Secondary Next.js dev server instance
* **Port 4200**: Angular CLI / Enterprise Micro-Frontends
* **Port 5173**: Vite default dev server

**Tooling Rule**: Diagnostics tools and Playwright runners MUST probe `[3000, 3001, 4200, 5173]` dynamically via `verify_application_health()` or `find_active_dev_url()` rather than hardcoding port 3000.

## 4. Canonical Page Recipes & Open Composition

The enterprise catalog provides 6 canonical layout recipes, each with complete `.tsx` boilerplate and companion `.spec.ts` Playwright test suites:

1. **`CrudTableRecipe`**: High-density enterprise table with search, status tags, bulk actions, and pagination.
2. **`MetricsDashboardRecipe`**: Executive KPI tiles, trend metrics, recent activity feed, and date range filters.
3. **`FormWizardRecipe`**: Progressive disclosure multi-step intake flow with step tracker and inline validation.
4. **`MasterDetailRecipe`**: Split-pane layout with searchable record directory on left and inspection drawer on right.
5. **`SettingsTabsRecipe`**: Tabbed portal governance layout covering domains, Entra ID MFA, and API secrets.
6. **`AuditTimelineRecipe`**: Chronological event stream with actor attribution, status change badges, and JSON telemetry diffs.

## 5. Input Modality Handling (PRD vs. Visual Mockup)

* **Natural Language PRD Branch**: Evaluates entity complexity, functional requirements, and primary workflows. Emits recommended routes with appropriate recipes or open compositions.
* **Visual Mockup Branch**: Extracts visual layout hierarchy from Figma, screenshots, or design assets. Decomposes into atomic grid containers, navigations, cards, and data surfaces without forcing rigid recipe templates.

---

## 6. Impeccable Refinement Protocol

Before finalizing any generated frontend page, run the Impeccable critique pass:
* `/distill`: Remove redundant grouping wrappers, clarify the primary visual metric, and balance typographic weight.
* `/polish`: Eliminate AI styling tells (random italicized words, AI beige backgrounds, inconsistent border radii).
* `/clarify`: Replace vague CTA labels ("Submit", "Click here") with action-oriented verbs ("Generate Invoice", "Confirm Appointment").
* `/harden`: Verify WCAG AA contrast (minimum 4.5:1), keyboard focus indicators, and error boundaries.
